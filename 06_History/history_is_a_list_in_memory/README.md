# The history is a list in memory

**Level:** 101 · you typed a command in one terminal and the up arrow in another cannot find it

**One line:** An interactive bash reads its history file into a list when it starts and writes the list back when it exits, so a command reaches the disk only when its shell ends. `HISTSIZE` sizes the list, `HISTFILESIZE` sizes the file, and a session that outgrows `HISTSIZE` writes its list over the file instead of adding to it. zsh works the same way under the names `HISTSIZE` and `SAVEHIST`. fish writes each command to its file as the command runs.

## Measured

Each session below is a real interactive bash, `bash -i`, whose typed lines come from a here-document. `--norc` keeps `~/.bashrc` out of it, and `HISTFILE` (or `HOME`) points into a scratch directory, so pasting these commands does not touch your own `~/.bash_history`. `2>/dev/null` drops what an interactive bash prints on stderr when its input is not a terminal: its prompts and the warning `no job control in this shell`.

```text

echo "HISTFILE=~/${HISTFILE##*/} HISTSIZE=$HISTSIZE HISTFILESIZE=$HISTFILESIZE"
EOF
HISTFILE=~/.bash_history HISTSIZE=500 HISTFILESIZE=500

$ HISTFILE=$PWD/hist bash --norc -i 2>/dev/null <<'EOF'
echo one
echo two
history
test -e hist && echo "hist exists" || echo "no hist file yet"
EOF
one
two
    1  echo one
    2  echo two
    3  history
no hist file yet

$ cat hist
echo one
echo two
history
test -e hist && echo "hist exists" || echo "no hist file yet"

$ HISTFILE=$PWD/hist bash --norc -i 2>/dev/null <<'EOF'
history
EOF
    1  echo one
    2  echo two
    3  history
    4  test -e hist && echo "hist exists" || echo "no hist file yet"
    5  history

$ HISTFILE=$PWD/hist bash --norc -i 2>/dev/null <<'EOF'
history -c
history -r
history -r
history
EOF
    1  history -r
    2  echo one
    3  echo two
    4  history
    5  test -e hist && echo "hist exists" || echo "no hist file yet"
    6  history
    7  history -r
    8  echo one
    9  echo two
   10  history
   11  test -e hist && echo "hist exists" || echo "no hist file yet"
   12  history
   13  history

$ printf 'echo old%s\n' 1 2 3 4 5 > big

$ HISTFILE=$PWD/big HISTSIZE=3 bash --norc -i 2>/dev/null <<'EOF'
echo "HISTSIZE=$HISTSIZE HISTFILESIZE=$HISTFILESIZE"
cat big
history
EOF
HISTSIZE=3 HISTFILESIZE=3
echo old3
echo old4
echo old5
    4  echo "HISTSIZE=$HISTSIZE HISTFILESIZE=$HISTFILESIZE"
    5  cat big
    6  history

$ printf 'echo old%s\n' 1 2 > small

$ HISTFILE=$PWD/small HISTSIZE=2 HISTFILESIZE=100 bash --norc -i 2>/dev/null <<'EOF'
echo a
EOF
a

$ cat small
echo old1
echo old2
echo a

$ HISTFILE=$PWD/small HISTSIZE=2 HISTFILESIZE=100 bash --norc -i 2>/dev/null <<'EOF'
echo b
echo c
echo d
EOF
b
c
d

$ cat small
echo c
echo d
```
<!-- /output -->

- **The defaults.** With nothing set, an interactive bash uses `~/.bash_history` and keeps 500 entries in memory and 500 lines on disk.
- **The file appears at exit.** Inside the first session, `history` lists its commands so far, and `test -e hist` finds no file. The file exists once the shell's input has ended. It holds all four lines, including the `test` that could not find it.
- **The next shell starts from the file.** Its `history` numbers the four saved lines 1 to 4, before any command of its own.
- **`history -r` adds to the list; it does not replace it.** `history -c` emptied the list, and each `history -r` then appended the file's five lines again: thirteen entries, and two copies of everything.
- **`HISTSIZE=3` keeps the last three entries**, and the numbers carry on from where the file left off: 4, 5, 6. `HISTFILESIZE` was not set, so it took `HISTSIZE`'s value, and bash cut the file down to three lines as it started. `cat big`, run inside the session, already shows only `old3` to `old5`.
- **A small `HISTSIZE` overrules a large `HISTFILESIZE`.** With `HISTSIZE=2 HISTFILESIZE=100`, a session that ran one command appended it after `old1` and `old2`. A session that ran three commands, more than its list can hold, wrote its list over the file instead, and `echo c` and `echo d` are all that is left. Two terminal windows sharing one file hit exactly this rule: see [Two terminals, one history file](../two_terminals_one_history_file/README.md).

- **`history -a` wrote nothing in bash 3.2** when the session had started with no history file or an empty one. `cat missing` found no file, and `cat empty` printed nothing. Bash 5.2 appended both lines in both cases. With one line already in the file, both versions appended. `history -a` is what the usual `PROMPT_COMMAND='history -a'` recipe runs at every prompt, so on a Mac that recipe inherits the same gap.
- **`history -c` followed by exit erased the file in bash 3.2.** The two old lines are gone, and `echo after` is all that is left. Bash 5.2 left them and appended.
- **`HISTSIZE=-1` means "keep everything" only in bash 5.2.** In bash 3.2 the same setting kept nothing: `history` printed no entries, and at exit the file was emptied, losing the two lines it had. A habit carried over from Linux can cost the whole file here.

zsh is the Mac's login shell, and what it saves with no startup file of your own comes from the system's `/etc/zshrc`. That differs too, so this key is also split:

```text
$ HOME=$PWD env -u ZDOTDIR -u TERM_PROGRAM -u TERM_SESSION_ID zsh -i 2>/dev/null <<'EOF'
echo "HISTFILE=[${HISTFILE#$HOME/}] HISTSIZE=$HISTSIZE SAVEHIST=$SAVEHIST"
```

```text
HISTFILE=[.zsh_history] HISTSIZE=2000 SAVEHIST=1000
```

<!-- /output -->

macOS's `/etc/zshrc` sets `HISTFILE=~/.zsh_history`, `HISTSIZE=2000` and `SAVEHIST=1000`, so zsh on a Mac saves history out of the box. Ubuntu's `/etc/zsh/zshrc` sets none of the three, leaving zsh's built-in defaults: no `HISTFILE`, a 30-entry list, and `SAVEHIST=0`. A zsh user on Ubuntu with no `~/.zshrc` saves no history at all. The example removes `TERM_PROGRAM` and `TERM_SESSION_ID` first because, inside Terminal.app, macOS's `/etc/zshrc` also loads Terminal's per-session history script, which [Two terminals, one history file](../two_terminals_one_history_file/README.md#on-a-mac) describes.

## In zsh and fish

**zsh** keeps a list and a file just as bash does. The list is `HISTSIZE` and the file is `SAVEHIST`. The builtin is `fc`, and zsh's `history` is `fc -l` under another name:

<!-- output:histmem_zsh -->
*Verified output of [`histmem_zsh.zsh`](examples/histmem_zsh.zsh), identical on Linux and macOS — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ zsh -f -i 2>/dev/null <<'EOF'
echo "HISTFILE=[$HISTFILE] HISTSIZE=$HISTSIZE SAVEHIST=$SAVEHIST"
EOF
HISTFILE=[] HISTSIZE=30 SAVEHIST=0

$ echo 'echo old' > hist

$ HISTFILE=$PWD/hist HISTSIZE=100 SAVEHIST=100 zsh -f -i 2>/dev/null <<'EOF'
echo new
fc -l 1
EOF
new
    1  echo new

$ cat hist
echo old

$ HISTFILE=$PWD/hist HISTSIZE=100 SAVEHIST=100 ZDOTDIR=$PWD zsh -d -i 2>/dev/null <<'EOF'
echo new
fc -l 1
cat hist
EOF
new
    1  echo old
    2  echo new
echo old

$ cat hist
echo old
echo new
fc -l 1
cat hist

$ HISTFILE=$PWD/hist HISTSIZE=100 SAVEHIST=2 ZDOTDIR=$PWD zsh -d -i 2>/dev/null <<'EOF'
echo last
EOF
last

$ cat hist
cat hist
echo last

$ HISTFILE=$PWD/now HISTSIZE=100 SAVEHIST=100 zsh -f -i 2>/dev/null <<'EOF'
echo written
fc -W
cat now
history -c 2>&1
EOF
written
echo written
fc -W
history: bad option: -c
```
<!-- /output -->

- **`zsh -f` has no history file.** With no startup files, `HISTFILE` is empty, the list holds 30 entries, and `SAVEHIST` is 0.
- **`zsh -f` ignores the file even when all three are set.** `fc -l 1` lists only `echo new`, and the file still says `echo old` afterwards. `-f` switches off the startup files, and with them, as measured here, the history file. That is worth knowing before you test history settings with `zsh -f`. The sessions that need the file use `zsh -d` instead, which skips only the system-wide startup files, with `ZDOTDIR` pointing at the empty scratch directory.
- **With `zsh -d` it is bash's model again.** The file is read at startup (`1 echo old`), untouched while the shell runs (`cat hist` inside still shows one line), and added to at exit.
- **`SAVEHIST=2` keeps the last two lines** of old and new together.
- **`fc -W` writes the list now**, as bash's `history -w` does. bash's `history -c` has no zsh spelling: `history: bad option: -c`.

| | bash | zsh |
|---|---|---|
| entries kept in memory | `HISTSIZE`, 500 by default | `HISTSIZE`: 30 under `zsh -f`, 2000 from macOS's `/etc/zshrc` |
| lines kept in the file | `HISTFILESIZE`, which takes `HISTSIZE`'s value if unset | `SAVEHIST`: 0 under `zsh -f`, 1000 from macOS's `/etc/zshrc` |
| the file | `~/.bash_history` | `$HISTFILE`: none under `zsh -f`, `~/.zsh_history` from macOS's `/etc/zshrc` |
| written | at exit | at exit |
| write the list now | `history -w` | `fc -W` |

**fish** has a file and no exit step:

```text
$ fish --no-config -c 'echo "fish_private_mode=[$fish_private_mode] fish_history=[$fish_history]"'
fish_private_mode=[1] fish_history=[]

$ printf "%s\n" "echo one" | fish --no-config -C "set -e fish_private_mode; set -e fish_history" -i
one

$ test -e ~/.local/share/fish/fish_history; and echo "fish_history exists"; or echo "no fish_history file"
no fish_history file

$ python3 $at_a_terminal "echo one" "cp ~/.local/share/fish/fish_history while-running"

$ string replace -r "when: \d+" "when: <epoch>" < while-running
- cmd: echo one
  when: <epoch>
- cmd: cp ~/.local/share/fish/fish_history while-running
  when: <epoch>
  paths:
    - ~/.local/share/fish/fish_history

$ string replace -r "when: \d+" "when: <epoch>" < ~/.local/share/fish/fish_history
- cmd: echo one
  when: <epoch>
- cmd: cp ~/.local/share/fish/fish_history while-running
  when: <epoch>
  paths:
    - ~/.local/share/fish/fish_history

$ fish --no-config -c 'set -e fish_private_mode; set -g fish_history work; history append "echo at work"'

$ ls ~/.local/share/fish
fish_history
work_history
```
<!-- /output -->

- **`fish --no-config` turns history off.** It sets `fish_private_mode` to 1 and `fish_history` to empty. Every fish example in this library runs with `--no-config`, so the ones about history undo both first.
- **A command piped into `fish -i` is run and not saved.** `one` was printed, and no history file was created. fish saves only lines its editor read from a terminal, so the typed commands here are typed at one: [`fish_at_a_terminal.py`](examples/fish_at_a_terminal.py) opens a pseudo-terminal with Python's `pty` module, types the lines, and throws away everything fish draws.
- **The file was written while fish was still running.** The second typed command copied the history file, and that copy already held both commands, the `cp` included. fish wrote `cp …` to the file before running it. There is no list to lose at exit.
- **The file is `~/.local/share/fish/fish_history`**, and `fish` in its name is the session: `set -g fish_history work` sent the next command to `work_history`. The `when:` and `paths:` lines are the subject of [Three history file formats](../three_history_file_formats/README.md).

For a fish user on a Mac, all of this holds as printed: the fish key is shared, fish 4.3.2 on macOS and on Ubuntu.
