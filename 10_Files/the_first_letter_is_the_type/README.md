# The first letter of `ls -l` is the type

**Level:** 101 · you have read `drwxr-xr-x` and `crw-rw-rw-`, and a table of what the first letter means

**One line:** The first character of `ls -l` is the file's type, not a permission: one of seven letters, and `test` and `find -type` use almost the same ones. What each type *is* shows when you open it: a FIFO waits and keeps nothing, a socket file refuses to open, and a symlink is `l` whether it points at a file, a device or nothing at all.

Chapter 2 of *The Ultimate Linux Shell Scripting Guide* gives this as a table of *file type designators*: `-` regular file, `d` directory, `c` character device, `b` block device, `p` named pipe, `s` socket, `l` symbolic link. A sentence on each type follows, then `find -type` to search for one. The letters are right. Some of the sentences are looser than the letters, and the scripts below make one of each type and check both.

## Measured

A user can make five of the seven types in a scratch directory. A socket file has no command of its own, so a one-line `python3` program binds one. `/dev/null` stands in for the character devices. No block device appears here, because making one needs root and the Linux image has none in `/dev` to borrow. The Mac's disk shows one [further down](#on-a-mac).

- **The letter is the type, and a symlink is its own type.** `alink` points at a regular file, `tonull` at a character device and `dangling` at a name that does not exist, and `ls -l` gives all three an `l`. `ls` does not look through a link unless you ask with `-L`.
- **`ls -F` marks four types after the name**: `/` directory, `@` symlink, `|` FIFO, `=` socket. A regular file gets no mark.
- **`test` has a flag per type**: `-f -d -L -p -S -b -c`. The socket flag is a capital `S`, because `-s` already meant "size greater than zero". Every flag except `-L` follows the link, so `alink` passes `-f` as well as `-L`, `tonull` passes `-c`, and `dangling` passes only `-L`: it is a symlink, but `-e` says it does not exist.
- **`find -type` uses the `ls` letters**, except `f` where `ls` prints `-`. Without `-L`, `find` reports all three links as `l`. With `-L` it follows them: `alink` becomes `f`, `tonull` becomes `c`, and only `dangling` is still `l`, because there is nothing to follow it to.
- Nothing matched `b`. Every line of this block was the same on Linux and macOS.

- **A directory** is a file, but not one `cat` can read: `Is a directory`.
- **`dangling` is listed, and cannot be opened.** `ls` found the name, and `open()` followed it to a name that does not exist.
- **Reading `tonull` read `/dev/null`**, and got zero bytes. A symlink can point at any type, not only at a file or a directory.
- **A FIFO keeps nothing.** The text went through `apipe` from `echo` to `cat`, and afterwards `ls` still reports a size of 0. The data passed through the kernel, not the disk. The writer was started first, and its `open()` waited until `cat` opened the other end.
- **A socket file cannot be opened at all.** It is also size 0, but where a FIFO's `open()` waits for a partner, a socket's fails at once: `No such device or address` on Linux, `Operation not supported on socket` on a Mac. A socket file is an address that a program `connect()`s to, and no program was listening. The Mac's `cat` prints an extra first line, `ai_family not supported`: BSD `cat` tries to connect to a socket it cannot open, and that attempt failed too.

### The book's sentences, checked

| The table says | What the runs show |
|---|---|
| a character device supplies a serial stream, a block device allows random access | on a Mac one disk is both: `/dev/disk0` is `b` and `/dev/rdisk0` is `c`, with one device number ([On a Mac](#on-a-mac)). The letter says which interface of the kernel the name goes through, not what kind of hardware is behind it |
| named pipes are devices | a FIFO is not a device: `test -c` and `test -b` are both false, `stat` calls it `fifo`, and it holds no data |
| sockets are named pipes that can also pass file descriptors and talk both ways | the two differ before any data moves: a FIFO opens, and a socket file refuses to. Passing descriptors and two-way traffic are what a connected Unix-domain socket does, and [unix(7) ↗](https://man7.org/linux/man-pages/man7/unix.7.html) describes both. No script here tests them |
| a symbolic link points to a regular file or a directory | `tonull` points to a character device, and `dangling` to nothing; both are `l` |

## On a Mac

The seven letters are the same, and so are `ls -F`, `test` and `find -type`. `stat`, which names the type in words, is not:

*Verified output of [`ftype_stat_sh.sh`](examples/ftype_stat_sh.sh) on **macOS** — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ stat -f "%Sp  %HT  %N" regular adir alink apipe asock /dev/null
-rw-r--r--  Regular File  regular
drwxr-xr-x  Directory  adir
lrwxr-xr-x  Symbolic Link  alink
prw-r--r--  Fifo File  apipe
srwxr-xr-x  Socket  asock
crw-rw-rw-  Character Device  /dev/null

$ stat -f "%Sp  %HT  %N" /dev/disk0 /dev/rdisk0
brw-r-----  Block Device  /dev/disk0
crw-r-----  Character Device  /dev/rdisk0

$ if [ "$(stat -f %r /dev/disk0)" = "$(stat -f %r /dev/rdisk0)" ]; then echo "one device number"; else echo "two device numbers"; fi
one device number
```
<!-- /output -->

- **Two `stat`s, two vocabularies.** GNU `stat` takes `-c` and a `%F` format and writes `regular empty file`, noticing the size, and `character special file`. BSD `stat` takes `-f` and `%HT` and writes `Regular File` and `Character Device`. A script that parses either one works on one system only. `ls -ld | cut -c1` and `test` work on both.
- **A symlink's own permissions.** Linux always shows `lrwxrwxrwx`, because the permissions of a link itself are never used there ([symlink(7) ↗](https://man7.org/linux/man-pages/man7/symlink.7.html)). The Mac stored the umask's `lrwxr-xr-x`.
- **One disk, two letters.** `/dev/disk0` is a block device and `/dev/rdisk0` a character device, with the same device number: one disk, reached through the kernel's block interface or its raw one. Linux has no `r` twin: its disks are block devices only.
- **An eighth letter.** `man ls` on a Mac lists `w`, a *whiteout*, which marks a deleted name in a union mount. Linux has no whiteout type for `ls` to show.
- **A character after the permissions.** On a Mac, `ls -l` can print `@` (extended attributes) or `+` (an access control list) right after the ten mode characters. That is why the scripts here keep only the first ten.

## In zsh and fish

**zsh** selects files by type inside the glob. A *glob qualifier* in parentheses after the pattern borrows `ls -F`'s marks for three types and a letter for the rest, and a `-` inside it follows symlinks:

<!-- output:ftype_letters_zsh -->
*Verified output of [`ftype_letters_zsh.zsh`](examples/ftype_letters_zsh.zsh), identical on Linux and macOS — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ echo *(.)
regular

$ echo *(/)
adir

$ echo *(@)
alink dangling tonull

$ echo *(p)
apipe

$ echo *(=)
asock

$ echo /dev/null(%c)
/dev/null

$ echo *(N%b)


$ echo *(-.)
alink regular

$ echo *(-%c)
tonull

$ echo *(-@)
dangling

$ [[ -S asock && -p apipe && -h dangling && ! -e dangling ]] && echo "[[ ]] takes the same letters as bash"
[[ ]] takes the same letters as bash
```
<!-- /output -->

`*(@)` is every symlink and `*(-@)` is only `dangling`: once links are followed, the only one still a link is the one that leads nowhere. That makes `*(-@)` the zsh way to find broken links. `N` in `*(N%b)` lets an empty match print nothing; without it zsh stops with `no matches found`, as [an unquoted `[:lower:]`](../../05_tr/an_unquoted_class_is_a_glob/README.md) shows. `[[ ]]` takes bash's flags, plus `-h` for a symlink.

**fish** has the same seven types twice: its `test` takes the one-letter flags, and `path filter -t` takes words.

<!-- output:ftype_letters_fish -->
*Verified output of [`ftype_letters_fish.fish`](examples/ftype_letters_fish.fish), identical on Linux and macOS — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ for op in -e -f -d -L -p -S -b -c; set -l hits; for f in * /dev/null; test $op $f; and set -a hits $f; end; echo "test $op: $hits"; end
test -e: adir alink apipe asock regular tonull /dev/null
test -f: alink regular
test -d: adir
test -L: alink dangling tonull
test -p: apipe
test -S: asock
test -b: 
test -c: tonull /dev/null

$ for t in file dir link fifo socket char block; echo "path filter -t $t:" (path filter -t $t * /dev/null); end
path filter -t file: alink regular
path filter -t dir: adir
path filter -t link: alink tonull
path filter -t fifo: apipe
path filter -t socket: asock
path filter -t char: tonull /dev/null
path filter -t block:

$ test -L dangling; echo "test -L dangling: $status"
test -L dangling: 0

$ path is -t link dangling; echo "path is -t link dangling: $status"
path is -t link dangling: 1

$ for f in *; test -L $f; and not test -e $f; and echo "broken: $f"; end
broken: dangling
```
<!-- /output -->

`test` agreed with bash on every file. `path filter` only passes a path that exists after following links, so `dangling` is missing from `-t link` even though `test -L` says it is one, and `path is -t link dangling` exits 1. To find a symlink whatever it points at, use `test -L` in fish.

| | bash | zsh | fish |
|---|---|---|---|
| is `f` a FIFO? a socket? | `[ -p f ]`, `[ -S f ]` | the same, or `[[ -p f ]]` | `test -p f`, `test -S f` |
| every symlink here | `find . -type l` | `echo *(@)` | `for f in *; test -L $f; and echo $f; end` |
| only broken symlinks | `find -L . -type l` | `echo *(-@)` | `for f in *; test -L $f; and not test -e $f; and echo $f; end` |
| a regular file, after following links | `[ -f f ]` | `echo *(-.)` | `test -f f`, or `path filter -t file` |

## If you are coming from another library

- **Encodings.** [File type is four questions ↗](https://masiarek.github.io/encodings-learning-library/06_Terminal/file_type_is_four_questions/index.html) starts where this page stops: the seven types are four bits of `st_mode`, and none of them says whether a regular file holds a PNG or a shell script. `file(1)`, the kernel's `execve` and a desktop each answer that differently.
- **Python.** [What kind of file is this? ↗](https://masiarek.github.io/python-learning-library/01_Text_and_Bytes/what_kind_of_file_is_this/index.html) asks for the same four bits with `os.lstat` and `stat.S_IFMT`, and shows `Path.is_file()` giving a dangling symlink and a missing file the same answer.
